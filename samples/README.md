# 샘플 — 형식 왕복 검증용

## `synthetic.svp`

**신스V 2가 우리 피치 컨트롤 점을 실제로 따라오는지 재기 위한 합성 파일이다.**

`web/src/core/transcribe/svp.ts`가 낸 것이고, 곡이 아니라 **답을 아는 신호**다:

| | |
|---|---|
| 템포·박자 | 139.5BPM · 4/4 (0.43초 간격 비트 64개) |
| 음표 | 8분음표 32개, A4~E5를 오르내린다 (`la`) |
| 커브 | **5.5Hz · ±35센트 비브라토**를 전 구간에 얹었다 |
| 컨트롤 점 | 323개 (원 프레임 1,380개에서 RDP로 줄인 것) |

### 왜 필요한가

**파일이 "열린다"와 "소리가 그 커브를 따른다"는 다르다.** 신스V 2의 Smart Pitch
Controls는 문서상 "AI 커브와 사용자 입력의 **공존**"이라 완전 대체가 아닐 수
있고, 그건 JSON을 아무리 들여다봐도 알 수 없다. 회귀 시험
(`web/test/svp.test.ts`)이 보증하는 것은 형식과 시간축까지다.

### 결과 — 통과 (2026-08-12)

**시간 보정 없이** 중앙값 오차 **4.1센트**(통과 기준 20센트), 20센트 안 91.9%,
비브라토 위상 상관 **r = 0.893**. 음표 계단 대비는 24.8센트이므로 신스V가 자기
커브를 만든 것이 아니라 **우리 점을 따라 불렀다.** 상수 지연 +9ms, 템포는
139.47 대 139.53으로 맞는다.

> **1차 렌더에서 버그를 하나 잡았다.** 그때는 템포가 120으로 떨어져 곡이 1.16배로
> 늘어났는데, 원인은 `time.startTimeSeconds`를 `0`(정수)으로 쓴 것이었다 — 신스V는
> 실수 필드를 `0.0`으로만 읽는다. **파일은 열리고 소리도 나서 JSON을 봐도 안 보였고,
> `JSON.parse`를 지나는 테스트로는 원리적으로 못 잡는다.** 지금은 회귀 시험이 원문
> 문자열을 본다.

### 재는 법

1. 신스V 2에서 이 파일을 연다 → 렌더 → WAV.
2. 그 WAV에서 f0를 도로 뽑는다:

```bash
cd server && .venv/bin/python scripts/extract_f0.py --out /tmp/roundtrip 렌더한파일.wav
```

3. 나온 커브를 이 파일의 `library[0].pitchControls`와 견준다.
   **중앙값 절대오차 20센트 안이면 통과.**

통과 못 하면 후퇴 순서: 점 밀도↑ → 노트를 짧게 끊어 AI 전이 여지를 줄이기 →
`parameters.pitchDelta`(SV1 경로) 병행 출력.

### 다시 굽는 법

앱에서 아무 곡이나 분석해 **`신스V 프로젝트 (피치 커브 포함)`**을 내려받으면
같은 종류의 파일이 나온다. 위 합성본은 `transcribe()` → `toSvp()`를 위 표의
값으로 직접 부른 것이라, 실곡과 달리 **정답을 알고 있다는 점**만 다르다.

배치로 굽는 것은 평가 하니스가 한다(`web/scripts/eval/pipeline.eval.ts`가 곡마다
`.svp`를 함께 낸다 — CLAUDE.md의 "평가 하니스" 절).
