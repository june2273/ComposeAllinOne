# 고음 보컬 f0가 무너진다 — 조사 인계 문서

**이 문서의 목적은 "다음 사람이 같은 실험을 반복하지 않게" 하는 것이다.**
2026-08-11~12에 이 문제를 파느라 모델 셋(RMVPE·basic-pitch·GAME)과 분리기 둘
(htdemucs·Mel-Band RoFormer)을 실제로 돌렸고, **다섯 가설 중 넷이 틀렸다.**
무엇을 재서 무엇이 틀렸는지가 아래에 전부 있다.

읽는 순서: §1 문제 → §2 확정 사실 → §3 죽은 가설 → §4 살아 있는 가설 →
§5 검색어와 후보 → §6 재현 방법.

배경은 [CLAUDE.md](../CLAUDE.md)의 "스템 분리 · 멜로디 전사" 절, 평가셋은
[evalset/README.md](../evalset/README.md).

## 1. 문제

보컬 멜로디를 MIDI·악보로 전사하는 파이프라인에서 **높은 음역의 음표가
사라진다.** 사용자가 앱에서 먼저 발견했고("고음 부분이 거의 짤린다"), 정답
MIDI로 확인됐다.

```
오디오 → [분리] → 보컬 스템 ┐
                             ├→ [f0 추정] → 커브 → [노트 분할] → [양자화] → MIDI/악보
       ──────── 원본 믹스 ──┘
```

**곡E**(원곡 보컬, 최고음 B♭5=932Hz, 정답 553음)에서 잰 값:

| 정답 음역 | 음표 수 | 정확히 맞힌 것 | **아예 못 낸 것** |
|---|---|---|---|
| 낮은 1/3 | 22 | 68% | 9% |
| 가운데 | 474 | 50% | 28% |
| **높은 1/3 (D♯5~A♯5)** | **57** | **26%** | **53%** |

A5는 7음 중 **0개**를 냈다.

**"아예 못 냈다"는 옥타브 오류가 아니다.** 그 자리에 음표 자체가 없다
(±150ms 안에 어떤 후보도 시작하지 않는다).

## 2. 확정 사실 — 재서 알아낸 것

측정 도구는 §6에 있다. **곡 하나(곡E)의 값이라는 한계를 먼저 적어 둔다** —
이 저장소는 곡을 늘렸을 때 결론이 뒤집힌 적이 두 번 있다.

### 2.1 유·무성 마스크는 범인이 아니다

고음 구간의 유성 프레임 비율이 **92~96%**로 다른 음역과 같다. 프레임은 살아
있는데 음정이 틀린다. 게이트(`app/audio.py:gate`)를 의심할 필요가 없다.

### 2.2 분리 스템에서는 서브하모닉으로 무너진다

htdemucs 보컬 스템, 고음 구간의 f0 오차 분포:

```
-12반음  28.2%   ← 한 옥타브 아래
-13반음  18.5%
-19반음   8.4%   ← 12도 아래 = 3배음을 기본음으로 봄
-20반음   6.6%
 +0반음   3.5%   ← 맞은 것
```

전부 ÷2·÷3 계열이다. 그래서 지금 파이프라인은 **음정을 원본 믹스에서 딴다**
(`melody.merge_voicing`: 음정은 믹스, 유·무성은 분리 스템).

### 2.3 그래도 믹스에서 22%뿐이고, 정보의 절반은 아예 없다

RMVPE는 프레임마다 360빈(20센트) salience를 낸다. 정답 음정이 몇 등인가:

| 믹스, 고음 | |
|---|---|
| 1등 = 정답 | 22.2% |
| 2등 | 11.5% |
| 3등 | 7.3% |
| **5등 밖** | **54.5%** |

→ **후보를 여럿 넘겨 노트 DP가 고르게 해도 천장이 41%다.** 절반 이상은 모델
출력 어디에도 정답이 없다.

### 2.4 두 f0 모델 다 고음에서 정확도가 반토막

같은 곡·같은 정답, 프레임 단위 "음정 맞음"(±50센트):

| 모델 · 입력 | 고음 F5+ | 중·저음 |
|---|---|---|
| basic-pitch · 믹스 | 6% | 11% |
| **RMVPE · 믹스** ← 현재 구성 | **23%** | **43%** |
| basic-pitch · htdemucs 스템 | 12% | 24% |
| RMVPE · htdemucs 스템 | 3% | 33% |
| basic-pitch · Mel-RoFormer 스템 | 9% | 24% |

**고음 열세는 RMVPE의 성질이 아니다** — 두 모델 모두 고음에서 중·저음의 절반쯤
된다. 모델을 갈아끼워 풀 문제가 아니라는 뜻이다.

### 2.5 f0 모델은 분리를 잘할수록 나빠진다 (RMVPE), 또는 반대다 (basic-pitch)

위 표의 중·저음 열을 입력별로 보면:

- **RMVPE**: 믹스 43% → htdemucs 33% → Mel-RoFormer 28%
- **basic-pitch**: 믹스 11% → htdemucs 24% → Mel-RoFormer 24%

**설계 의도 그대로다.** RMVPE는 폴리포닉 믹스에서 보컬을 찾도록 학습됐고
(Wei et al., Interspeech 2023), basic-pitch는 다성 전사기라 보컬을 떼어 줘야
가장 센 악기를 안 따라간다. **깨끗한 독창은 RMVPE에게 학습 분포 밖이다.**

이것이 `merge_voicing`("음정은 믹스에서")이 왜 맞았는지의 설명이다 — 당시엔
실측으로만 알고 이유를 몰랐다.

### 2.6 분리는 고음 기본음을 죽이지 않는다 (가설 반박)

기본음 대 배음 에너지 비(STFT 8192, ±0.5반음 대역, 고음 구간):

| | 기본음/2배음 | 기본음/3배음 |
|---|---|---|
| 원본 믹스 | 1.36 | 1.60 |
| htdemucs 스템 | 1.57 | 5.35 |
| Mel-RoFormer 스템 | 1.48 | **9.66** |

분리 스템은 기본음을 **더 도드라지게** 남긴다. 그리고 정답 자리 대비 한 옥타브
아래의 에너지는 0.10~0.12뿐이라 **정답 MIDI도 맞다**(귀카피 옥타브 오기가
아니다).

→ **"기본음이 없어서 서브하모닉으로 간다"는 설명은 틀렸다.** 기본음은 있다.

### 2.7 오디오를 한 옥타브 내려서 물으면 개선된다 — 유일하게 움직인 지표

RMVPE에 넣는 표본화율을 절반이라고 속이면 오디오가 한 옥타브 내려가고 두 배
길어진다. 나온 f0에 ×2, 시각에 ÷2를 하면 원래 자리로 돌아온다.

| | 고음 1등 | 고음 상위3 | 중·저음 1등 | 중·저음 상위3 |
|---|---|---|---|---|
| 그대로 | 22.2% | 41.1% | 42.7% | 69.4% |
| **한 옥타브 아래** | **29.6%** | **59.3%** | 44.2% | 72.0% |

**"정답이 아예 없다"가 59% → 41%로 줄었다.** 다른 음역도 나빠지지 않는다.
아직 최종 음표까지 재지 않았다(살아 있는 가설 §4.1).

## 3. 죽은 가설 — **다시 시도하지 말 것**

| # | 가설 | 반박 | 근거 |
|---|---|---|---|
| H1 | 게이트/유·무성 마스크가 고음을 잘라낸다 | ✗ | 고음 유성률 92~96% (§2.1) |
| H2 | 분리기(htdemucs)가 나빠서다. SOTA 분리기로 바꾸면 낫다 | ✗ | Mel-RoFormer(SDR 13.29 대 8.04)로 갈아도 고음 1등 3.3% 대 3.1%. 누설 지표도 13.0 대 13.3 dB로 동일 |
| H3 | 모노 다운믹스로 정위 단서를 버려서 분리가 나빴다 | ✗ | 진짜 스테레오(좌우 상관 0.78)로 넣어도 3.3% → 3.3% |
| H4 | 분리가 고음 **기본음**을 깎아 서브하모닉이 된다 | ✗ | 기본음/3배음이 믹스 1.60 → 스템 9.66. 오히려 더 남는다 (§2.6) |
| H5 | 이전 멜로디 모델(basic-pitch)이 고음에 강했다 | ✗ | 같은 입력에서 6% 대 23%로 RMVPE 압승. 게다가 basic-pitch도 고음에서 반토막 (§2.4) |
| H6 | 정답 MIDI가 한 옥타브 높게 적혔다(귀카피 오기) | ✗ | 한 옥타브 아래 에너지가 정답 자리의 0.10~0.12 (§2.6) |
| H7 | RMVPE의 주파수 상한에 걸린다 | ✗ | 360빈 × 20센트 + 오프셋 1997.38센트 → **상한 약 2006Hz**(B6). B♭5=932Hz는 여유 있게 안쪽 |
| H8 | confidence 문턱(`MIN_CONFIDENCE`)이 고음을 버린다 | ✗ | 0.01·0.03·0.1·0.3 넷 모두 최종 음표 611개로 동일(2026-08-11 기록) |

**H2는 특히 값비싼 오답이었다.** 913MB 가중치 + 의존성 3개를 붙이고 이식까지
끝낸 뒤 되돌렸다. SDR은 우리 지표가 아니다 — 사양서 §1.4가 "SAR을 보라"고 한
이유가 이것이고, 실제로는 **SAR도 아니라 f0 모델의 학습 분포**가 지배했다.

## 4. 살아 있는 가설

### 4.1 옥타브 2패스 (증거 있음, 미완)

§2.7에서 salience 순위가 실제로 올랐다. **남은 일**: 두 패스를 어떻게 합칠지
(센트 축을 맞춰 salience를 더하고 argmax? 신뢰도 가중?) 정하고, **최종 음표
정확도**로 재기. 지금 있는 것은 순위 지표뿐이다.

### 4.2 "고음에서 반토막"의 진짜 원인이 따로 있다 (미조사)

두 모델이 같은 패턴을 보이는데(§2.4) 원인을 모른다. 후보:

- **학습 데이터의 음역 분포.** MIR-1K·MDB-melody 등 f0 학습셋은 남성·중음역
  보컬이 지배적일 수 있다. 고음 표본이 적으면 두 모델이 같은 편향을 갖는 것이
  자연스럽다. → **데이터셋의 f0 히스토그램을 확인할 것.**
- **멜 스펙트로그램의 고역 분해능.** RMVPE는 128멜 밴드(30~8000Hz @ 16kHz).
  932Hz 근처에서 멜 밴드 하나가 덮는 폭이 반음보다 넓으면 기본음과 옆 음이
  같은 밴드에 들어간다. → **밴드 폭 대 반음 폭을 계산해 볼 것.** 옥타브 2패스가
  듣는 이유의 후보이기도 하다(내리면 분해능이 좋은 구간으로 들어간다).
- **반주와의 충돌.** 고음 보컬은 신스·기타 상성부와 음역이 겹친다.

### 4.3 경계 헤드(onset+frame)가 애초에 옳은 구조다 (부분 확인)

- GAME(openvpi) 경계로 재발음 회수가 네 곡 모두에서 올랐다(31~55% → 55~78%).
  다만 가중치가 **CC BY-NC-SA 4.0**이라 채택 보류.
- 우리 ODF 봉우리로 같은 일을 절반 했다(회수 34~52% → 39~68%, 유령 거의 불변).
  **현재 코드에 들어 있다**(`core/transcribe/notes.ts`의 `onsetPeaks`).
- Mel-RoFormer 논문(Wang·Lu·Chen, ISMIR 2024)의 전사 모델도 onset+frame 예측기
  구조다. COnPOff **.625**(MIR-ST500)로 SpecTNT .550, JDCnote .422를 앞선다.
  **가중치 미공개로 보인다** — 논문이 가리키는 것은 구조 코드와 설정뿐.

### 4.4 다중 후보 f0 + DP (천장 41%)

salience 상위 k개를 사이드카가 내보내고 `notes.ts`의 DP가 연속성으로 고르는
구조. 층 경계에 맞고(사이드카는 신호만, 판단은 core) 새 모델이 필요 없지만,
**§2.3의 천장이 41%다.** 4.1과 함께 써야 의미가 있다.

## 5. 검색을 위한 재료

### 5.1 문제를 부르는 이름

영어로 찾을 때 쓸 말. 우리 증상은 여러 문헌 용어에 걸쳐 있다.

- `subharmonic error` / `octave error in f0 estimation` / `pitch halving`
- `singing voice melody extraction high pitch` / `soprano f0 estimation`
- `note-level singing transcription` / `automatic singing transcription (AST)`
- `vocal note segmentation onset offset` / `repeated note segmentation`
- `out-of-domain f0 estimation isolated vocals vs mixture`
  ← §2.5는 이 말로 찾아야 한다. "분리하면 f0가 나빠진다"는 흔한 서술이 아니다.
- `pitch range bias in melody extraction training data`

### 5.2 우리가 이미 돌려 본 것

| 이름 | 무엇 | 라이선스 | 결과 |
|---|---|---|---|
| [RMVPE](https://github.com/Dream-High/RMVPE) (`rmvpe-onnx`) | f0, 폴리포닉 학습 | 코드 MIT / 가중치 사슬 3단 | **채택 중.** 고음 23%(믹스) |
| [basic-pitch](https://github.com/spotify/basic-pitch) | 다성 전사 | Apache-2.0 | 제거됨. 고음 6% |
| [GAME](https://github.com/openvpi) (segmenter+estimator) | 경계 헤드 | 코드 MIT / **가중치 CC BY-NC-SA 4.0** | 방향 확인, 라이선스로 보류 |
| [htdemucs](https://github.com/adefossez/demucs) | 스템 분리 | 코드 MIT / 가중치 미표기 | **채택 중** |
| [Mel-Band RoFormer](https://github.com/lucidrains/BS-RoFormer) (Kim Vocal 2) | 스템 분리 | 코드 MIT / 가중치 MIT(2026-04-22 GPL-3.0에서 재라이선스) | 이식했다가 롤백. 효과 없음 |

### 5.3 아직 안 본 후보

- **JDC / JDCnote** — Kum & Nam. RWC-Pop 학습이라 J-pop 도메인. Keras 2.2.2에
  묶여 있는 것이 걸림돌. 사양서 §8.
- **FCPE**, **PESTO**(Riou et al., ISMIR 2023 — self-supervised, 경량),
  **CREPE**(Kim et al., ICASSP 2018 — 옥타브 오류의 고전 baseline)
- **ROSVOT**(ACL 2024, MIT) — robust singing voice transcription, 노트 레벨
- **SOME**(openvpi) — GAME과 같은 계열, 라이선스 확인 필요
- **MIR-ST500**(york135) baseline — **라이선스 미표기**
- **VOCANO**, **Sheet Sage**, **Omnizart**
- 데이터셋: **MIR-1K**, **MIR-ST500**, **POP909**, **MedleyDB / MDB-melody-synth**,
  **Vocadito**, **iKala** — §4.2의 음역 분포를 확인할 대상

### 5.5 물어볼 질문 (조사자용)

1. **f0 학습셋의 음역 분포가 알려져 있는가?** 고음(F5+) 표본이 실제로 희소한가?
   그렇다면 §2.4의 "두 모델이 같이 반토막"이 설명된다.
2. **옥타브 시프트(피치 시프트 후 f0 추정 → 되돌리기)를 쓴 선행 연구가 있는가?**
   있다면 합치는 규칙을 어떻게 정했는가. 없다면 왜 안 쓰는가(우리가 모르는
   함정이 있을 수 있다).
3. **"분리 스템이 f0 추정을 악화시킨다"는 보고가 문헌에 있는가?** §2.5는 우리
   실측이지만 곡 하나다. 같은 관찰이 있으면 강하게 뒷받침된다.
4. **onset+frame 전사 가중치 중 상업적으로 쓸 수 있는 것이 있는가?**
   (GAME은 NC, Mel-RoFormer 전사본은 미공개로 보임)
5. **RMVPE의 멜 밴드가 900Hz 부근에서 반음을 가르는가?** 128밴드 30~8000Hz
   기준으로 계산 가능하다.

## 6. 재현 방법

측정 스크립트는 이번 조사에서 임시로 만든 것이라 **저장소에 없다**(스크래치패드).
아래는 무엇을 만들면 되는지의 명세다. 저장소에 있는 하니스는
[CLAUDE.md](../CLAUDE.md)의 "평가 하니스 — 세 조각이다" 절에 있다.

| 재는 것 | 방법 |
|---|---|
| 음역대별 회수율 | 정답 음표마다 ±150ms 안에 같은 음이름의 후보가 시작하는가. 정확 / 옥타브만 다름 / 시각만 / 없음으로 분류 |
| f0 오차 분포 | 정답 음표 구간의 유성 프레임에서 `round(추정 − 정답)` 반음 히스토그램 |
| salience 순위 | `RMVPE.predict()`의 넷째 반환값(360×T). 정답 음정 ±50센트 대역의 최대값보다 **큰 봉우리가 몇 개** 있는가 = 정답의 등수 |
| 분리 누설 | 정답에 음표가 없는 구간(±0.2초 여유) 대 있는 구간의 rms 비(dB). f0를 안 거치므로 분리 품질만 본다 |
| 기본음 보존 | STFT 8192, 정답 기본음·2배음·3배음 자리(±0.5반음)의 에너지 비 |
| 옥타브 2패스 | `RMVPE.predict(audio, rate // 2)` — 표본화율을 속이면 한 옥타브 내려가고 두 배 길어진다. f0 ×2, 시각 ÷2 |

정답 곡·슬롯 대응은 `evalset/songs.json`, 오디오와 스템은 `server/cache/<슬롯>/`.

**주의 — 이 저장소에서 실제로 데인 것들**

- **곡 하나로 판단하지 말 것.** 곡을 늘렸을 때 결론이 뒤집힌 것이 두 번이다
  (`merge_voicing` 입력 선택, GAME 채택 여부). 정답이 있는 곡은 지금 넷뿐이다.
- **대리 지표로 방향을 정하지 말 것.** 게이트가 만든 신호로 게이트를 평가해서
  순환 논증에 빠진 적이 있다.
- **지표들이 서로 얽혀 있다.** 음 선택이 좋아지면 "자리 일치"가 저절로 오른다
  (RMVPE 교체 때 46% → 88%). 양자화를 안 건드렸는데도 그렇다.
- **SDR을 보고 고르지 말 것.** H2가 그 실패다.
