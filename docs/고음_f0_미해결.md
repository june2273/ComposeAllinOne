# 고음 보컬 f0가 무너진다 — 조사 인계 문서

**이 문서의 목적은 "다음 사람이 같은 실험을 반복하지 않게" 하는 것이다.**
2026-08-11~12에 이 문제를 파느라 f0 모델 넷(RMVPE·basic-pitch·GAME·FCPE)과
분리기 둘(htdemucs·Mel-Band RoFormer)을 실제로 돌렸고, **세운 가설 열 중
아홉이 틀렸다.** 무엇을 재서 무엇이 틀렸는지가 아래에 전부 있다.

> **2026-08-18에 네 가지가 바뀌었다.**
>
> 1. **기전을 찾았다**(§2.8). 분해능이 아니라 **배음 수**다. 그래서 모델을
>    갈아끼워 풀 문제가 아니라는 것이 관측이 아니라 **설명**이 됐다.
> 2. **옥타브 2패스를 실제로 붙였다**(§4.1). 정답 6곡에서 F5+ 정확률이 오르고
>    −12 옥타브 오류가 내려간다. **처음으로 살아남은 가설이다.**
> 3. **보컬 후처리는 범인이 아니다**(H10 · §3.2). 마스크를 가공 전 스템으로 갈아도
>    F5+ 정확률이 6곡 모두 0.1%p 안에서 같다 — **음정은 후처리를 거치지 않는다.**
> 4. **겨냥이 틀렸다는 것이 드러났다**(H12 · §3.4). 음표 레벨로 재니 F5+ 정답 중
>    옥타브 오류는 0~3개뿐이고 **58~67%는 음표가 아예 안 선다.** 옥타브를 완벽히
>    고쳐도 고음 회수율은 26% → 32%가 천장이다. **다음 조사는 여기서 시작할 것.**
>
> 그리고 **모델 교체 후보 6개를 조사해 전부 탈락시켰다**(§5.3). 다시 파기 전에
> 그 표부터 읽을 것 — ROSVOT은 MIT에 SOTA를 주장하지만 **RMVPE f0를 입력으로
> 받아서** 우리 오류를 그대로 물려받는다.

읽는 순서: §1 문제 → §2 확정 사실 → §3 죽은 가설 → §4 살아 있는 가설 →
§5 검색어와 후보 → §6 재현 방법.

배경은 [CLAUDE.md](../CLAUDE.md)의 "스템 분리 · 멜로디 전사" 절, 평가셋은
[evalset/README.md](../evalset/README.md).

## 1. 문제

보컬 멜로디를 MIDI·악보로 전사하는 파이프라인에서 **높은 음역의 음표가
사라진다.** 사용자가 앱에서 먼저 발견했고("고음 부분이 거의 짤린다"), 정답
MIDI로 확인됐다.

```
오디오 → [분리] → 보컬 스템 ┐
                             ├→ [f0 추정] → 커브 → [노트 분할] → [양자화] → MIDI/악보
       ──────── 원본 믹스 ──┘
```

**곡E**(원곡 보컬, 최고음 B♭5=932Hz, 정답 553음)에서 잰 값:

| 정답 음역 | 음표 수 | 정확히 맞힌 것 | **아예 못 낸 것** |
|---|---|---|---|
| 낮은 1/3 | 22 | 68% | 9% |
| 가운데 | 474 | 50% | 28% |
| **높은 1/3 (D♯5~A♯5)** | **57** | **26%** | **53%** |

A5는 7음 중 **0개**를 냈다.

**"아예 못 냈다"는 옥타브 오류가 아니다.** 그 자리에 음표 자체가 없다
(±150ms 안에 어떤 후보도 시작하지 않는다).

**2026-08-18에 곡B(작곡가 - 곡B)의 정답이 생겼다** — 338음 · D♯4~A5 ·
**F5 이상이 50음(14.8%)**로 평가셋에서 고음 비율이 가장 높다. 사용자가 이 곡에서
문제를 다시 보고했고, 재 보니 프레임 단위로 **F5 이상 정확률 32.5%(커버2
커버) · −12 옥타브 오류 36.2%**였다.

> **같은 곡의 커버가 둘 있는 것이 값이 크다.** 반주가 같고 보컬만 다른데
> 옥타브 오류가 **36.2% 대 8.6%**로 4배 갈린다. `곡F` 쌍이 템포 문턱의
> 심판인 것처럼, 이 쌍이 **고음 문턱의 심판**이다 — 한쪽만 좋아지는 값은
> 고르지 않는다.

## 2. 확정 사실 — 재서 알아낸 것

측정 도구는 §6에 있다. **곡 하나(곡E)의 값이라는 한계를 먼저 적어 둔다** —
이 저장소는 곡을 늘렸을 때 결론이 뒤집힌 적이 두 번 있다.

### 2.1 유·무성 마스크는 범인이 아니다

고음 구간의 유성 프레임 비율이 **92~96%**로 다른 음역과 같다. 프레임은 살아
있는데 음정이 틀린다. 게이트(`app/audio.py:gate`)를 의심할 필요가 없다.

### 2.2 분리 스템에서는 서브하모닉으로 무너진다

htdemucs 보컬 스템, 고음 구간의 f0 오차 분포:

```
-12반음  28.2%   ← 한 옥타브 아래
-13반음  18.5%
-19반음   8.4%   ← 12도 아래 = 3배음을 기본음으로 봄
-20반음   6.6%
 +0반음   3.5%   ← 맞은 것
```

전부 ÷2·÷3 계열이다. 그래서 지금 파이프라인은 **음정을 원본 믹스에서 딴다**
(`melody.merge_voicing`: 음정은 믹스, 유·무성은 분리 스템).

### 2.3 그래도 믹스에서 22%뿐이고, 정보의 절반은 아예 없다

RMVPE는 프레임마다 360빈(20센트) salience를 낸다. 정답 음정이 몇 등인가:

| 믹스, 고음 | |
|---|---|
| 1등 = 정답 | 22.2% |
| 2등 | 11.5% |
| 3등 | 7.3% |
| **5등 밖** | **54.5%** |

→ **후보를 여럿 넘겨 노트 DP가 고르게 해도 천장이 41%다.** 절반 이상은 모델
출력 어디에도 정답이 없다.

### 2.4 두 f0 모델 다 고음에서 정확도가 반토막

같은 곡·같은 정답, 프레임 단위 "음정 맞음"(±50센트):

| 모델 · 입력 | 고음 F5+ | 중·저음 |
|---|---|---|
| basic-pitch · 믹스 | 6% | 11% |
| **RMVPE · 믹스** ← 현재 구성 | **23%** | **43%** |
| basic-pitch · htdemucs 스템 | 12% | 24% |
| RMVPE · htdemucs 스템 | 3% | 33% |
| basic-pitch · Mel-RoFormer 스템 | 9% | 24% |

**고음 열세는 RMVPE의 성질이 아니다** — 두 모델 모두 고음에서 중·저음의 절반쯤
된다. 모델을 갈아끼워 풀 문제가 아니라는 뜻이다.

### 2.5 f0 모델은 분리를 잘할수록 나빠진다 (RMVPE), 또는 반대다 (basic-pitch)

위 표의 중·저음 열을 입력별로 보면:

- **RMVPE**: 믹스 43% → htdemucs 33% → Mel-RoFormer 28%
- **basic-pitch**: 믹스 11% → htdemucs 24% → Mel-RoFormer 24%

**설계 의도 그대로다.** RMVPE는 폴리포닉 믹스에서 보컬을 찾도록 학습됐고
(Wei et al., Interspeech 2023), basic-pitch는 다성 전사기라 보컬을 떼어 줘야
가장 센 악기를 안 따라간다. **깨끗한 독창은 RMVPE에게 학습 분포 밖이다.**

이것이 `merge_voicing`("음정은 믹스에서")이 왜 맞았는지의 설명이다 — 당시엔
실측으로만 알고 이유를 몰랐다.

### 2.6 분리는 고음 기본음을 죽이지 않는다 (가설 반박)

기본음 대 배음 에너지 비(STFT 8192, ±0.5반음 대역, 고음 구간):

| | 기본음/2배음 | 기본음/3배음 |
|---|---|---|
| 원본 믹스 | 1.36 | 1.60 |
| htdemucs 스템 | 1.57 | 5.35 |
| Mel-RoFormer 스템 | 1.48 | **9.66** |

분리 스템은 기본음을 **더 도드라지게** 남긴다. 그리고 정답 자리 대비 한 옥타브
아래의 에너지는 0.10~0.12뿐이라 **정답 MIDI도 맞다**(귀카피 옥타브 오기가
아니다).

→ **"기본음이 없어서 서브하모닉으로 간다"는 설명은 틀렸다.** 기본음은 있다.

### 2.7 오디오를 한 옥타브 내려서 물으면 개선된다 — 유일하게 움직인 지표

RMVPE에 넣는 표본화율을 절반이라고 속이면 오디오가 한 옥타브 내려가고 두 배
길어진다. 나온 f0에 ×2, 시각에 ÷2를 하면 원래 자리로 돌아온다.

| | 고음 1등 | 고음 상위3 | 중·저음 1등 | 중·저음 상위3 |
|---|---|---|---|---|
| 그대로 | 22.2% | 41.1% | 42.7% | 69.4% |
| **한 옥타브 아래** | **29.6%** | **59.3%** | 44.2% | 72.0% |

**"정답이 아예 없다"가 59% → 41%로 줄었다.** 다른 음역도 나빠지지 않는다.

**2026-08-18에 이것이 채택으로 이어졌다** — 정답 6곡에서 프레임 정확률로 다시
재고 병합 규칙을 정해 파이프라인에 넣었다(§4.1). 기전은 §2.8.

### 2.8 기전 — 분해능이 아니라 **배음 수**다 (실측 2026-08-18)

오래 "고음에서 왜 반토막이 나는가"를 몰랐고, 후보로 **멜 분해능**을 적어 뒀다.
계산해 보니 **틀렸다 — 분해능은 고음에서 오히려 좋다.**

RMVPE 프런트엔드(16kHz · 128멜 · 30~8000Hz · n_fft 1024):

| 음 | 멜 밴드 간격 | STFT 빈/반음 | **8kHz 안의 배음 수** |
|---|---|---|---|
| C3 (131Hz) | 2.00 반음 | 0.50 | **61** |
| A4 (440Hz) | 0.84 반음 | 1.67 | 18 |
| A♯5 (932Hz) | **0.57 반음** | 3.55 | **8** |
| C6 (1047Hz) | 0.54 반음 | 3.98 | 7 |

가르는 것은 **배음 수**다. ÷2 가설(한 옥타브 아래)의 배음은 참 배음과 짝수
자리에서 **전부 겹치므로**, 배음이 8개뿐이면 그것을 기각할 증거가 거의 없다.
저음에서는 61개가 있어 홀수 자리 배음의 부재가 즉시 드러난다.

**이것은 가중치가 아니라 입력 표현의 성질이다.** 그래서:

- §2.4의 "두 모델이 나란히 반토막"이 우연이 아니라 **필연**이다. 멜/스펙트로그램을
  먹는 모델은 무엇이든 같은 함정에 빠진다(H5·H9가 관측한 그대로다).
- **§2.7의 옥타브 2패스가 왜 듣는지도 같은 계산이 설명한다** — A♯5를 한 옥타브
  내리면 466Hz가 되어 배음이 **8개에서 17개로** 는다.

재현: `12 * log2((f + 멜밴드간격) / f)` 와 `8000 // f`. 도구가 필요 없다.

| H2 | 분리기(htdemucs)가 나빠서다. SOTA 분리기로 바꾸면 낫다 | ✗ | Mel-RoFormer(SDR 13.29 대 8.04)로 갈아도 고음 1등 3.3% 대 3.1%. 누설 지표도 13.0 대 13.3 dB로 동일 |
| H3 | 모노 다운믹스로 정위 단서를 버려서 분리가 나빴다 | ✗ | 진짜 스테레오(좌우 상관 0.78)로 넣어도 3.3% → 3.3% |

| H8 | confidence 문턱(`MIN_CONFIDENCE`)이 고음을 버린다 | ✗ | 0.01·0.03·0.1·0.3 넷 모두 최종 음표 611개로 동일(2026-08-11 기록) |
| H9 | 두 번째 f0 모델(FCPE)에게 물어 옥타브 오류만 교정한다 | ✗ | 정답 4곡 전부에서 **정확률이 내려갔다.** 심판을 어디에 걸어도 개선이 없다 (§3.1) |
| H10 | 보컬 **후처리**(HPF·게이트·정규화)가 고음을 잘라낸다. 가공 전 스템을 쓰면 낫다 | ✗ | 마스크를 원본 스템으로 갈아도 **F5+ 정확률이 6곡 모두 0.1%p 안에서 같다.** 오히려 유령이 는다 (§3.2) |
| H11 | 분쟁 프레임의 **스펙트럼 에너지**로 옥타브를 심판한다(진짜 음이 위면 아래 자리가 비어 있을 것) | ✗ | e(X)/e(2X) 중앙값이 위가 정답일 때 0.227 대 아래일 때 0.152로 **겹친다.** 믹스의 X 자리가 반주에 오염된다 (§3.3) |
| H12 | 고음 소실의 주범은 **옥타브 오류**다 | ✗ | 음표 레벨 실측: F5+ 정답 중 옥타브 오류는 0~3개뿐이고 **58~67%는 음표가 아예 안 선다** (§3.4) |

### 3.1 H9 — FCPE 옥타브 교차검증 (실측 2026-08-12)

**두 모델이 다투게 하면 옥타브를 가릴 수 있으리라 기대했고, 틀렸다.**

발상은 이랬다. RMVPE는 폴리포닉 믹스로 학습됐고 FCPE(Luo et al., 2025)는
M4Singer·VCTK를 DDSP로 재합성한 의사 라벨로 학습해 **깨끗한 단선율 보컬에
강하다.** 성격이 상보적이니 분리 보컬에 FCPE를 걸어 "옥타브가 틀렸는가"만 묻고,
둘이 정확히 옥타브만큼 어긋난 구간을 다수결로 통째로 옮기면(`f0 *= 2**s`)
미세 음정을 건드리지 않고 옥타브만 고칠 수 있다고 봤다.

정답 MIDI 4곡에 대해 프레임별로 **정답 음표 대비 50센트 안에 든 비율**을 쟀다.

| 곡 | 지금 (RMVPE믹스+마스크) | 심판=분리보컬 | 심판=믹스 |
|---|---|---|---|
| 곡A\* | **11.6%** | 11.6% | 8.8% |
| 곡C | **59.2%** | 49.0% | 50.6% |
| 곡D | **54.7%** | 53.2% | 49.6% |
| 곡E | **43.1%** | 15.2% | 30.8% |

\* 곡A의 정답 MIDI는 오디오보다 +2반음 조옮김돼 있다(반음차 봉우리가 −2에
선다). 절대값은 못 쓰지만 **같은 정답을 네 변형에 똑같이 대므로 비교는 유효하다.**

**어느 곡에서도 오르지 않았다.** 이유는 둘이고, 둘 다 이미 알고 있던 사실의
따름정리였다.

1. **분리 보컬에 건 FCPE는 분리 아티팩트를 물려받는다.** 곡E에서 FCPE 단독의
   반음차 봉우리가 **−12에 35.5%**로 섰다 — `merge_voicing`이 "음정은 믹스에서"로
   옮겨 가며 고친 바로 그 증상이다(RMVPE도 분리 보컬 위에서는 옥타브 오류가
   64개였다). **스템 위에서 도는 추정기는 무엇이든 같은 함정에 빠진다.**
   심판이 교정한 것이 아니라 병을 옮겨 온 것이다.
2. **믹스에 건 FCPE는 보컬을 안 따라간다.** 반음차가 −19·−31·−39처럼 넓게
   퍼졌다(곡D에서 −39가 4.0%, −41이 2.8%) — 반주의 저역을 따라간 것이다.
   FCPE는 단선율 모델이라 애초에 폴리포닉을 가릴 수단이 없다.

**즉 심판으로 쓸 수 있는 신호가 없었다.** 분리 보컬은 옥타브가 이미 틀려 있고,
믹스는 보컬을 못 고른다. RMVPE가 믹스에서 음정을 잡고 스템에서 마스크를 받는
지금 조합이 **시험한 다섯 가지 중 최선**이다.

부수적으로 확인한 것:

- FCPE의 속도 주장은 사실이다 — 분리 보컬 4분 곡에 1~3초(CPU). 다만 믹스에서는
  55~95초로 뛰었다.
- `torchfcpe`는 MIT이고 torch 위에서 돈다(torchaudio 등 4개를 끌고 온다).
  **되돌리면서 전부 제거했다** — 되살릴 때 `pip install torchfcpe` 하나면 된다.
- 재현: `docs/` 옆이 아니라 평가 하니스로 돌렸다. 절차는 §6과 같고, 커브 두 벌을
  프레임별로 정답에 대는 것이 전부다.

> **이 저장소가 같은 자리에서 세 번째로 데였다.** `merge_voicing`은 대리 지표
> 때문에, GAME은 곡이 하나여서, 이번에는 **모델의 성격만 보고 입력 신호를 안
> 따져서.** 규칙은 매번 같다 — **정답에 대 보기 전에는 방향을 정하지 말 것.**

### 3.2 H10 — 보컬 후처리가 범인인가 (실측 2026-08-18)

**"후처리가 고음을 죽이는 것 아니냐"는 자연스러운 의심이고, 틀렸다.**

먼저 **후처리 보컬이 어디에 쓰이는지**를 정확히 볼 것. 여기서 착각이 생긴다.

| 후처리 보컬(`vocal_processed.wav`)이 주는 것 | 주지 않는 것 |
|---|---|
| **유·무성 마스크**(`merge_voicing`의 뒤 인자) | **음정** — 그건 원본 믹스에서 온다 |
| **재발음 온셋**(ODF 봉우리) | |

즉 **음정은 후처리를 한 번도 거치지 않는다.** 그래서 후처리가 고음 음정을
망칠 경로는 원리적으로 하나뿐이다 — 게이트가 고음 프레임을 닫아 마스크가
그 자리를 지워 버리는 것.

**두 가지를 쟀다.**

1. **게이트가 고음에서 열려 있는가.** 정답 음표 구간 기준으로 F5 이상에서
   `100 / 100 / 100 / 52 / 96 / 100%`다(곡 순서는 아래 표와 같다). 곡C만
   낮은데, 그 곡은 **원본 스템에서도 70%**라 게이트가 아니라 분리·릴리스 꼬리의
   문제다.
2. **마스크를 원본 스템으로 갈아 끼우고 정확률을 다시 쟀다.**

| 곡 | 마스크 | C5미만 | C5~E5 | **F5+** | 전체 | 유령 위험 |
|---|---|---|---|---|---|---|
| 곡A | 후처리 | 72.1% | 70.2% | **58.5%** | 71.4% | 17.0% |
| | 원본 스템 | 72.1% | 70.3% | **58.5%** | 71.5% | 17.6% |
| 곡B (커버2) | 후처리 | 79.2% | 39.0% | **42.3%** | 61.5% | 57.7% |
| | 원본 스템 | 79.2% | 39.1% | **42.4%** | 61.6% | 56.7% |
| 곡B (커버1) | 후처리 | 66.2% | 62.0% | **50.7%** | 62.3% | 30.3% |
| | 원본 스템 | 65.9% | 62.7% | **50.7%** | 62.3% | 30.3% |
| 곡C | 후처리 | 87.0% | 81.8% | **86.4%** | 84.9% | 8.5% |
| | 원본 스템 | 87.0% | 81.7% | **86.4%** | 84.9% | 8.6% |
| 곡D | 후처리 | 62.4% | 51.1% | **26.9%** | 57.5% | 5.9% |
| | 원본 스템 | 62.5% | 51.1% | **26.9%** | 57.5% | 6.0% |
| 곡E | 후처리 | 58.6% | 56.2% | **39.6%** | 55.8% | 33.9% |
| | 원본 스템 | 58.7% | 56.2% | **39.6%** | 55.8% | **37.8%** |

**F5 이상이 여섯 곡 모두 0.1%p 안에서 같다.** 얻을 것이 없고, 곡E에서는
유령 위험이 33.9 → 37.8%로 오른다.

**왜 이렇게까지 같은가** — `merge_voicing`이 보는 것은 게이트가 만든 파형이
아니라 **그 파형에 RMVPE를 돌린 결과의 `f0 > 0`**이다. RMVPE는 무음 구간을
이미 스스로 무성이라고 하므로, 게이트가 0으로 만드는 자리는 대부분 **RMVPE가
어차피 무성이라 할 자리**다. 즉 마스크에 관한 한 게이트는 거의 항등이다.

> **그렇다고 후처리를 빼도 된다는 뜻은 아니다.** 마스크에는 거의 무영향이지만
> **ODF 온셋은 후처리 보컬에 건다** — 거기서는 게이트가 잡음 봉우리를 눌러
> 준다(믹스에 걸었을 때 유령이 78 → 137로 늘었던 그 자리다). 이 실험이 말하는
> 것은 "후처리는 고음의 범인이 아니다"까지다.

**가공 전 스템은 이미 쓸 수 있다** — `stems/vocals.wav`로 저장되고 분석 콘솔에서
재생·내려받기가 된다. 파이프라인이 안 쓸 뿐이고, 위 표가 그 이유다.

### 3.3 H11 — 스펙트럼 에너지 심판 (실측 2026-08-18)

**"진짜 음이 X+12라면 X 자리(서브하모닉)에는 에너지가 없을 것"**은 §2.6이 실제로
관측한 성질이라(정답 자리 대비 아래 옥타브가 0.10~0.12) 심판으로 쓸 수 있어
보였다. **분쟁 프레임에서 재 보니 안 갈린다.**

STFT 8192로 기준 f0 자리 X와 그 옥타브 위 2X의 ±0.5반음 대역 최대값을 재고
비율 e(X)/e(2X)로 판정했다:

| | 위(X+12)가 정답 | 아래(X)가 정답 |
|---|---|---|
| 곡B 커버1 (371프레임) | 0.227 | 0.152 |
| 곡E (808프레임) | 0.402 | 0.252 |

**분포가 겹친다.** 어떤 문턱에서도 오발이 회수를 앞선다(곡B 문턱 0.25에서
회수 60.5% · 오발 70.9%). §2.6이 깨끗하게 갈렸던 것은 **정답 음표 구간 전체를
평균**했기 때문이고, 분쟁이 나는 프레임은 정의상 애매한 자리다. 게다가 우리가
보는 것은 믹스라 X 자리가 **베이스·화음악기에 오염**된다.

> **이것으로 프레임 단위 심판 후보가 셋 다 죽었다** — confidence 분위수(§4.1의
> 보수적 문턱이 그 한계다) · 제2모델(H9) · 스펙트럼 에너지(H11). 남은 축은
> **시간(연속성)**뿐이고, 그것이 §4.4다.

### 3.4 H12 — 고음 소실의 주범은 옥타브가 아니다 (실측 2026-08-18)

**이 저장소가 오래 잘못 겨냥하고 있던 것이다.** 사용자가 "후렴이 통째로 날아간다"고
보고했고, 옥타브 오류를 의심해 §4.1·§4.4를 붙였다. **음표 레벨에서 초 단위로
재 보니 옥타브는 곁가지였다.**

정답 음표 ±150ms 안에 우리 음표가 시작하는가(템포 추정과 무관한 측정):

| 곡 | F5+ 정답 | 정확 | **옥타브** | 다른 음 | **음표 자체가 없음** |
|---|---|---|---|---|---|
| 곡B (커버2) | 50 | 13 | **3** | 5 | **29 (58%)** |
| 곡B (커버1) | 50 | 14 | **0** | 5 | **31 (62%)** |
| 곡C | 48 | 16 | **0** | 0 | **32 (67%)** |
| 곡E | 40 | 10 | **0** | 8 | **22 (55%)** |
| 곡D | 29 | 12 | 0 | 7 | 10 (34%) |
| 곡A | 7 | 3 | 0 | 1 | 3 (43%) |

**옥타브 오류는 0~3개인데 "아예 없음"이 22~32개다.** 즉 옥타브를 완벽히 고쳐도
고음 회수율은 26% → 최대 32%까지밖에 못 간다.

§1이 처음부터 "**아예 못 낸 것 53%**"라고 적어 놨는데, 그 뒤 조사가 §2.2의
서브하모닉 분포에 끌려 옥타브로 좁혀졌다. **두 숫자는 다른 것을 말하고 있었다** —
§2.2는 "유성 프레임의 음정이 틀린다", §1은 "음표가 안 선다". 프레임이 절반쯤
맞아도(F5+ 프레임 정확률 48~56%) 음표가 안 서는 이유는 아직 모른다. 후보:

- **온셋이 ±150ms를 벗어난다** — 프레임은 맞는데 시작 시각이 틀리면 이 지표에서
  "없음"으로 잡힌다. `자리 일치`가 40~60%인 것과 같은 문제일 수 있다.
- **`minNoteMs`(80ms)·`SWITCH_MS`(70ms)에 걸려 사라진다** — 고음은 짧게 스치는
  경우가 많고, 곡B는 185BPM이라 16분음표가 81ms다. **경계값에 정면으로 걸린다.**
- **유·무성 마스크가 고음의 짧은 음을 못 살린다.**

**다음 조사는 이 셋을 가르는 것부터다.** 옥타브를 더 파지 말 것.

**H2는 특히 값비싼 오답이었다.** 913MB 가중치 + 의존성 3개를 붙이고 이식까지
끝낸 뒤 되돌렸다. SDR은 우리 지표가 아니다 — 사양서 §1.4가 "SAR을 보라"고 한
이유가 이것이고, 실제로는 **SAR도 아니라 f0 모델의 학습 분포**가 지배했다.

## 4. 살아 있는 가설

### 4.1 옥타브 2패스 — **채택됐다** (2026-08-18)

`melody.resolve_octave_pass`. 가설 아홉 중 **처음으로 살아남은 것이다.**
새 모델도 새 의존성도 새 라이선스도 없다 — `extract_f0_from_samples(x, rate // 2)`
한 줄이 전부다(기전은 §2.8).

**병합 규칙**은 넷을 모두 만족할 때만 올린다. 느슨하게 열면 이득은 커지지만
(F5+ 평균 +7~9%p) **반드시 어느 한 곡의 전체 정확률이 내려간다.**

1. 두 패스가 같은 프레임에서 유성
2. 두 커브가 **정확히 한 옥타브** 차이(±50센트)
3. 기준 패스가 자기 기준으로 자신 없음(분위수 순위 < 0.6)
4. 2패스가 자기 기준으로 자신 있음(순위 > 0.6)

+ 다수결 창 5프레임(50ms).

- **confidence는 절대값으로 비교할 수 없다** — 실측 중앙값이 0.177 대 0.556이라
  큰 쪽을 고르면 늘 2패스가 이긴다. **패스 안에서의 분위수 순위**로 잰다.
- **동점은 같은 순위를 받아야 한다.** 커브의 confidence가 소수 셋째 자리에서
  반올림돼 있어 동점이 흔한데, `argsort().argsort()`를 쓰면 같은 값이 배열
  순서대로 0~1에 흩뿌려져 발동이 통째로 죽는다(실측).
- **음역 문턱은 두지 않았다.** MIDI 74 아래로는 **아무 일도 하지 않았고**(조건 2가
  이미 저역을 지킨다) 76 위로는 오히려 곡을 퇴행시켰다.
- 0.6/0.6은 **네 이웃이 전부 안전한 유일한 격자점**이라 골랐다. 6곡으로 정한
  값이니 곡이 늘면 다시 볼 것.

**프레임 단위 실측** (정답 6곡, `scripts/f0_truth.py`):

| 곡 | F5+ 정확 | F5+ −12오류 | 전체 정확 | 발동 |
|---|---|---|---|---|
| 곡A | 48.7 → **57.2%** | 19.3 → **10.7%** | 70.2 → 70.4% | 1.8% |
| 곡B (커버2) | 32.5 → **42.1%** | 36.2 → **26.7%** | 57.1 → **61.2%** | 2.8% |
| 곡B (커버1) | 47.6 → **48.8%** | 8.6 → **7.4%** | 60.4 → 60.7% | 1.3% |
| 곡C | 78.3 → **82.4%** | 5.9 → **1.8%** | 83.4 → 83.8% | 0.3% |
| 곡D | 26.7 → 26.7% | 0.2 → 0.2% | 56.2 → 56.2% | 0.0% |
| 곡E | 32.7 → **38.9%** | 8.2 → **2.1%** | 53.4 → **55.2%** | 1.5% |

**어느 곡의 전체 정확률도 내려가지 않는다.** 바뀌는 프레임이 0~2.8%뿐이라
보수적인 값이다(곡B 커버1의 `C5 미만`만 65.2 → 64.6%로 0.6%p 내려간다).

> **음표 레벨로는 거의 안 움직인다.** 곡E에서 `정확`이 176 → 183인데 음표 총수도
> 450 → 464라 **정밀도는 그대로다.** 고음역만 보면 오히려 `정답에 없음`이 7 → 12로
> 는다 — f0가 맞아 음표가 서기 시작했지만 **시작 시각이 틀려서** 매칭 창을 벗어난다.
> 즉 이 변경의 이득은 **커브에는 온전히 실리고 음표에는 안 실린다.**
> 리듬 표기는 별개의 미해결 문제다(CLAUDE.md의 "자리 일치" 40~60%).
>
> **그래도 값이 있다** — `.svp` 피치 커브는 프레임 f0가 **그대로 산출물**이라
> 여기서는 이 개선이 100% 전달된다.

### 4.2 학습 데이터의 음역 분포 (미조사)

§2.8이 기전을 설명했지만 **그것만으로 전부는 아닐 수 있다.** 남은 후보:

- **f0 학습셋의 음역 분포.** MIR-1K·MDB-melody 등은 남성·중음역 보컬이 지배적일
  수 있다. → **데이터셋의 f0 히스토그램을 확인할 것.**
- **반주와의 충돌.** 고음 보컬은 신스·기타 상성부와 음역이 겹친다.

> **"멜 스펙트로그램의 고역 분해능" 후보는 죽었다** — 계산해 보니 분해능은
> 고음에서 **오히려 좋다**(§2.8의 표). 다시 세우지 말 것.

### 4.3 경계 헤드(onset+frame)가 애초에 옳은 구조다 (부분 확인)

- GAME(openvpi) 경계로 재발음 회수가 네 곡 모두에서 올랐다(31~55% → 55~78%).
  다만 가중치가 **CC BY-NC-SA 4.0**이라 채택 보류.
- 우리 ODF 봉우리로 같은 일을 절반 했다(회수 34~52% → 39~68%, 유령 거의 불변).
  **현재 코드에 들어 있다**(`core/transcribe/notes.ts`의 `onsetPeaks`).
- Mel-RoFormer 논문(Wang·Lu·Chen, ISMIR 2024)의 전사 모델도 onset+frame 예측기
  구조다. COnPOff **.625**(MIR-ST500)로 SpecTNT .550, JDCnote .422를 앞선다.
  **가중치 미공개로 보인다** — 논문이 가리키는 것은 구조 코드와 설정뿐.

### 4.4 다중 후보 f0 + DP — **채택했다. 그런데 이득이 작다** (2026-08-18)

프레임 단위 심판이 셋 다 죽은 뒤(H9·H11, §4.1의 보수적 문턱) 남은 축은
**시간(연속성)**뿐이었다. 그래서 옥타브 후보를 사이드카가 `f0.json`의
`f0Alt`로 싣고, `notes.ts`의 Viterbi DP가 국소 비용을
`min(|기준−p|, |후보−p|)`로 계산해 **프레이즈 단위로** 고르게 했다.
층 경계 그대로다 — 사이드카는 신호만, 판단은 `core/transcribe`.

- 후보는 **정확히 ±1옥타브** 관계인 프레임만(사이드카 `octave_candidate`가
  거르고 `notes.ts`가 외부 입력이므로 다시 확인한다).
- **전이 비용은 상수 그대로**라 O(프레임×상태)가 유지된다.
- `centsOffset`은 프레임마다 음표에 가까운 후보로 재고, 반옥타브 밖은 뺀다 —
  안 그러면 후보를 따라간 음표의 값이 ±1200에 끌려간다.
- **추론 비용 0** — 2패스는 §4.1이 이미 돌리고 있다.

**음표 회수율 실측**(정답 ±150ms, 초 단위라 템포 추정과 무관):

| 곡 | C5미만 정확/옥타브 | C5~E5 정확/옥타브 | F5+ 정확/옥타브 | 유령 |
|---|---|---|---|---|
| 곡B (커버2) | 115/0 → 115/0 | 22/8 → **27/4** | 12/4 → **13/3** | 4 → 4 |
| 곡B (커버1) | 83/0 → 82/1 | 29/0 → 29/0 | 13/1 → **14/0** | 3 → 3 |
| 곡E | 158/10 → **162/7** | 104/2 → **105/1** | 10/0 → 10/0 | 32 → 33 |
| 곡A · 곡C · 곡D | 변화 없음 | 변화 없음 | 변화 없음 | −1 / 0 / 0 |

**설계대로 동작한다 — 옥타브 오류가 정확으로 바뀐다**(곡E 10→7, 곡B 8→4).
유령은 늘지 않는다. **그런데 총량이 곡당 +1~5음뿐이다.**

**이유는 H12다** — 애초에 옥타브 오류가 F5+ 정답의 0~3개뿐이었다. 이 장치는
있는 오류를 정확히 고치지만, **고음이 사라지는 주된 이유가 그것이 아니었다.**

> **§2.3의 "천장 41%"는 이 장치의 천장이 아니다.** 그 값은 기준패스 salience
> 상위 k개의 천장이고, 여기서 쓰는 후보는 옥타브 2패스라 성격이 다르다
> (§2.7에서 상위3이 41% → 59%). 다만 **어느 쪽이든 음표가 서지 않으면 소용없다.**

## 5. 검색을 위한 재료

### 5.1 문제를 부르는 이름

영어로 찾을 때 쓸 말. 우리 증상은 여러 문헌 용어에 걸쳐 있다.

- `subharmonic error` / `octave error in f0 estimation` / `pitch halving`
- `singing voice melody extraction high pitch` / `soprano f0 estimation`
- `note-level singing transcription` / `automatic singing transcription (AST)`
- `vocal note segmentation onset offset` / `repeated note segmentation`
- `out-of-domain f0 estimation isolated vocals vs mixture`
  ← §2.5는 이 말로 찾아야 한다. "분리하면 f0가 나빠진다"는 흔한 서술이 아니다.
- `pitch range bias in melody extraction training data`

## 6. 재현 방법

**음역대별 지표는 이제 저장소에 있다**(2026-08-18).

```bash
cd server
.venv/bin/python scripts/f0_truth.py --all --variant octave2   # 프레임 단위, 음역대별
```

```bash
# 음표 단위. 정답 구간 밖을 유령으로 세지 않고, 템포가 다르면 경고한다
server/.venv/bin/python web/scripts/eval_transcribe.py 정답.mid 우리.mid --register
```

> **곡B는 음표 단위 지표를 읽지 말 것.** 우리 템포 추정이 92.7BPM(정답 185)이라
> 박 기준 비교가 통째로 무의미하다. `eval_transcribe.py`가 이제 그 경우 경고를
> 띄운다. 프레임 단위(`f0_truth.py`)는 초 기준이라 영향받지 않는다.

나머지 측정(살리언스 순위·분리 누설·기본음 보존)은 여전히 임시 스크립트다.
아래는 무엇을 만들면 되는지의 명세다. 저장소에 있는 하니스는
[CLAUDE.md](../CLAUDE.md)의 "평가 하니스 — 세 조각이다" 절에 있다.

| 재는 것 | 방법 |
|---|---|
| 음역대별 회수율 | 정답 음표마다 ±150ms 안에 같은 음이름의 후보가 시작하는가. 정확 / 옥타브만 다름 / 시각만 / 없음으로 분류 |
| f0 오차 분포 | 정답 음표 구간의 유성 프레임에서 `round(추정 − 정답)` 반음 히스토그램 |
| salience 순위 | `RMVPE.predict()`의 넷째 반환값(360×T). 정답 음정 ±50센트 대역의 최대값보다 **큰 봉우리가 몇 개** 있는가 = 정답의 등수 |
| 분리 누설 | 정답에 음표가 없는 구간(±0.2초 여유) 대 있는 구간의 rms 비(dB). f0를 안 거치므로 분리 품질만 본다 |
| 기본음 보존 | STFT 8192, 정답 기본음·2배음·3배음 자리(±0.5반음)의 에너지 비 |
| 옥타브 2패스 | `RMVPE.predict(audio, rate // 2)` — 표본화율을 속이면 한 옥타브 내려가고 두 배 길어진다. f0 ×2, 시각 ÷2 |

정답 곡·슬롯 대응은 `evalset/songs.json`, 오디오와 스템은 `server/cache/<슬롯>/`.

**주의 — 이 저장소에서 실제로 데인 것들**

- **곡 하나로 판단하지 말 것.** 곡을 늘렸을 때 결론이 뒤집힌 것이 두 번이다
  (`merge_voicing` 입력 선택, GAME 채택 여부). 정답이 있는 곡은 지금 넷뿐이다.
- **대리 지표로 방향을 정하지 말 것.** 게이트가 만든 신호로 게이트를 평가해서
  순환 논증에 빠진 적이 있다.
- **지표들이 서로 얽혀 있다.** 음 선택이 좋아지면 "자리 일치"가 저절로 오른다
  (RMVPE 교체 때 46% → 88%). 양자화를 안 건드렸는데도 그렇다.
- **SDR을 보고 고르지 말 것.** H2가 그 실패다.
